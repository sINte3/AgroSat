# TASK_027_ALEMBIC_INIT_AND_FIRST_MIGRATION.md

## Objective

Initialize Alembic for the existing AgroSat backend, connect it to the current SQLAlchemy model metadata, and create a safe baseline migration for the already-populated Supabase PostgreSQL/PostGIS database.

This task is schema-control work only. Do not change API behavior, frontend code, NDVI backfill logic, Sentinel Hub logic, or production data.

## Critical Safety Rule

The Supabase database already physically contains production tables and real data, including 275 fields and NDVI history. The first Alembic migration must not execute `CREATE TABLE`, `DROP TABLE`, `ALTER TABLE`, `DELETE`, `TRUNCATE`, or any destructive DDL/DML against the existing Supabase database.

The correct approach is:

1. Initialize Alembic files.
2. Configure Alembic to read `DATABASE_URL` from the existing `.env` through `backend/config.py`.
3. Configure Alembic to import all SQLAlchemy models and use `Base.metadata`.
4. Create a no-op baseline revision for the existing schema.
5. Stamp the existing Supabase database to that baseline revision.
6. Run an autogenerate drift check and inspect it.
7. Do not apply autogenerated DDL unless it has been separately reviewed and approved.

## Step 4 — Patch `backend/alembic/env.py`

Patch the generated `backend/alembic/env.py`. Do not replace unrelated generated comments unless needed.

### 4.1 Add project imports and model registration

At the top of `env.py`, after the generated imports, add this block:

```python
from pathlib import Path
import sys

from sqlalchemy import engine_from_config, pool

BACKEND_DIR = Path(__file__).resolve().parents[1]
if str(BACKEND_DIR) not in sys.path:
    sys.path.insert(0, str(BACKEND_DIR))

from config import settings
from database import Base
from models.enterprise import Enterprise
from models.crop import CropType
from models.field import Field, CropSeason
from models.monitoring import NDVIRecord, Alert, ScoutingNote, User
```

The explicit model imports are required. Without them, `Base.metadata` may be incomplete and Alembic autogenerate will produce false destructive diffs.

### 4.2 Replace `target_metadata = None`

Find:

```python
target_metadata = None
```

Replace with:

```python
target_metadata = Base.metadata
```

### 4.3 Add object filtering for PostGIS/Supabase internal tables

Add this helper before `run_migrations_offline()`:

```python
POSTGIS_INTERNAL_TABLES = {
    "spatial_ref_sys",
    "geometry_columns",
    "geography_columns",
}


def include_object(object_, name, type_, reflected, compare_to):
    if type_ == "table" and reflected and compare_to is None:
        if name in POSTGIS_INTERNAL_TABLES:
            return False
    return True
```

This prevents Alembic from treating PostGIS metadata tables as application tables that should be dropped.

### 4.4 Patch offline migrations

Inside `run_migrations_offline()`, make sure the URL is read from `settings.database_url` and passed to `context.configure`.

The relevant configuration must include:

```python
url = settings.database_url
context.configure(
    url=url,
    target_metadata=target_metadata,
    literal_binds=True,
    dialect_opts={"paramstyle": "named"},
    include_object=include_object,
    compare_type=True,
    compare_server_default=False,
    include_schemas=False,
    version_table="alembic_version",
)
```

### 4.5 Patch online migrations for Supabase pooler safety

Inside `run_migrations_online()`, make sure Alembic uses `NullPool` and reads the URL from `settings.database_url`.

Use this connection setup logic:

```python
configuration = config.get_section(config.config_ini_section, {})
configuration["sqlalchemy.url"] = settings.database_url
connectable = engine_from_config(
    configuration,
    prefix="sqlalchemy.",
    poolclass=pool.NullPool,
)

with connectable.connect() as connection:
    context.configure(
        connection=connection,
        target_metadata=target_metadata,
        include_object=include_object,
        compare_type=True,
        compare_server_default=False,
        include_schemas=False,
        version_table="alembic_version",
    )

    with context.begin_transaction():
        context.run_migrations()
```

`NullPool` is intentional. The project connects through the Supabase connection pooler on port 6543. Alembic should open a short-lived migration connection and release it immediately, not maintain its own long-lived SQLAlchemy pool.

No special custom schema is required for `alembic_version`. Keep it as `public.alembic_version` through the default search path. Do not put Alembic versioning into Supabase internal schemas such as `auth`, `storage`, or `extensions`.

The revision id must be exactly:


Do not add table creation logic to this baseline migration.

## Step 9 — Disable Silent Table Creation After Baseline

After the baseline is stamped and verified, patch `backend/database.py` so runtime startup no longer creates tables with `Base.metadata.create_all(bind=engine)`.

Find this block inside `init_db()`:

```python
    from models.enterprise import Enterprise
    from models.crop import CropType
    from models.field import Field, CropSeason
    from models.monitoring import NDVIRecord, Alert, ScoutingNote, User
    with engine.connect() as conn:
        conn.execute(text("CREATE EXTENSION IF NOT EXISTS postgis"))
        conn.commit()
    Base.metadata.create_all(bind=engine)
```

Replace it with:

```python
    with engine.connect() as conn:
        conn.execute(text("CREATE EXTENSION IF NOT EXISTS postgis"))
        conn.commit()
```

Rationale: from this task onward, schema changes must go through Alembic migrations. Leaving `Base.metadata.create_all()` in application startup defeats schema discipline and can silently create new tables outside migration history.

Do not remove `init_db()` from `backend/main.py` in this task.
